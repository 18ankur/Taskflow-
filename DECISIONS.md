# TaskFlow — Design Decisions

## 1. Why this product and approach?

I chose to design TaskFlow, a simple task-management product for people who
want to organize their daily work without unnecessary complexity.

I chose a static HTML, CSS and JavaScript implementation instead of using a
component framework because the assignment focuses on a single responsive
homepage. A framework would introduce additional setup and dependencies
without providing enough value for this small product experience.

The homepage focuses on showing the product immediately rather than making
large marketing claims. The hero contains an interactive task card so users
can understand what TaskFlow does within a few seconds.

I intentionally avoided fabricated testimonials, fake customer counts,
fake company logos and unsupported statistics.

## 2. One trade-off made under the time limit

I prioritized the homepage experience and interactive task demonstration
instead of building a complete task-management application with a backend.

The task card is functional on the front end: users can mark tasks as
complete, add a task and see the progress percentage update.

With a real week, I would build authentication, persistent task storage,
task categories, due dates, reminders and a full dashboard.

## 3. Where did you use AI tools?

AI tools were used during brainstorming and for generating an initial
implementation structure and copy ideas.

I personally reviewed and modified the layout, product concept, responsive
behavior, interaction logic and content.

I also verified that the page does not depend on fabricated testimonials,
fake user numbers or fake company logos, in accordance with the assignment
requirements.
